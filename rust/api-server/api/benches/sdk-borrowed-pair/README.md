# Borrow a cacheless live delete/insert pair before allocating event vectors

**Keep the SDK change.** Across 12 alternating release pairs on CPU 5, wire
decode through callback delivery used **13.05% less thread CPU** (median paired
change). The candidate won all 12 pairs on CPU and retired instructions.
Both builds delivered **245,643 callbacks for 104,116 transactions**, with the
same ordered content checksum `bb0c984258351b7a`. [Raw measurements](samples.jsonl).

| Main replay | Baseline median | Candidate median | Median paired change |
|---|---:|---:|---:|
| Thread CPU ms / 1,000 tx | 0.65352 | 0.57626 | −13.05% |
| User instructions, billions / process | 4.179 | 3.679 | −11.97% |
| User cycles, billions / process | 1.477 | 1.302 | −12.51% |
| Burst p99, µs | 33.54 | 31.67 | −9.37% (8/12 lower) |
| Service p99, µs | 1.750 | 1.625 | −2.18% (7/12 lower) |
| Allocation calls / capture | 2,792,155 | 1,952,705 | −30.06% |

Of 232,860 table changes, 209,863 had the exact pair shape. Avoiding temporary
vectors saved **839,450 allocation calls** across the full replay. The fallback
control had **622 captured transactions**, repeated 168 times; CPU was
0.70683 → 0.70391 ms/1,000 (−0.86% paired, 9/12 lower). This control used
**0.56% more instructions**, but showed no median CPU slowdown and had identical
allocations (2,111,424) and ordered checksum (`82ac3bb258ee8048`). It tests the
other shapes in this recording, not every possible table mix.

## What the A/B covers

Both executables start at SDK `842b520c2509b1cec478878a7a05e5f7bec6a906`.
They share a single copy of the current regional bindings generated by that CLI
(`module_bindings/mod.rs` SHA-256 `b68926f6f27e6dcfff16d67294b053af09eb1c3a05cde0303697c1b15cf80bc6`).
Only the candidate uses [the SDK patch](borrowed-pair.patch).

The existing generated API first constructs the diff, then optionally supplies
a key projection. The cacheless candidate represents **exactly one live delete
and one live insert** as references to the decoded rows. Before matching, or
when the keys differ, the two ordinary callbacks remain observable. Equal
keys become a single `(old, new)` update. This skips two raw-event vectors and
two matched-reference vectors on a match. Other shapes and initial snapshots
use the existing lists; with `client-cache` the borrowed variant is compiled out.

The [existing SDK replay](../sdk-live/main.rs) measures resident wire bytes
through envelope and typed decoding, normal transaction processing, PK pairing
and callback delivery. Timing excludes network I/O, application logic and SQL.
The main workload is the full ordered region-14 capture. A separate
[shape control](fallback.rs) keeps whole transactions in which **no table**
has one delete and one insert after grouping table chunks across query sets.
It repeats that subsequence in wire order to at least the original frame count.
The parity pass hashes callback kind, table name and serialized old/new rows.

CPU is current-thread CPU over four full passes after a warm-up. Each sample is
a fresh process pinned to CPU 5 (Ryzen 9 9950X3D, rustc 1.100.0). Twelve adjacent A/B blocks alternate order.
`perf stat` instructions and cycles include startup, the warm-up and timed passes;
allocation calls (including reallocations) come from a separate build. Burst
and service p99s use separate runs and the [sdk-live definitions](../sdk-live/README.md).

## Reproduce

Use the working-tree generated bindings for the SDK revision above, Cargo's
offline dependencies, `perf`, `taskset`, Bun, and the private `region14.wire`
(SHA-256 `c5c7878915085400621d32396d72a8d93c37ca80e6e2fc13859a3613a3bb3997`).
If the transient wire copy has expired, use the SDK's
`heap-replay prepare "$PRIVATE_STDBCAP1" "$WIRE"` and verify that digest.
`$out` is a fresh, nonexistent directory. Both release binaries use opt-level 3,
fat LTO, line tables, the cacheless SDK and mimalloc v3.

```sh
python3 build.py "$SDK_REPO" "$out"
python3 measure.py "$out" "$WIRE" 5 > "$out/samples.jsonl"
python3 summary.py < "$out/samples.jsonl"
```

`build.py` also runs the [loopback fixture](../sdk-owned-initial/lifecycle.rs)
with and without client caching. It exercises populated and empty initial
snapshots, borrowed-before-owned ordering, live inserts, reducer updates,
unsubscribe and disconnect. The SDK library tests exercise different PKs,
pointer identity, one-sided batches, duplicate FIFO pairing and event order
on both sides of the small-batch cutoff.

On the SDK checkout, `cargo test --locked --offline -p spacetimedb-sdk --lib`
passed with the default cache (39 passed), `--no-default-features` (37 passed)
and `--no-default-features --features retain-row-bytes` (37 passed). Each skips
one explicitly ignored microbenchmark. Both loopback lifecycle runs passed.
